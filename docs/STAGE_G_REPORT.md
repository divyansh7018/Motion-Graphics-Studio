## 1. What was built

### 1.1 The backend layer

* `app/ai/backend.py` - the shared `AIBackend` behaviour: capabilities, health
  checks, model listing, settings schema, descriptions.
* `app/ai/registry.py` - `AIBackendManager`: build, detect, enable/disable,
  configure, test, refresh, models, defaults.
* `app/ai/video_backends/` - `standard` (fixture), `command`, `http`, `comfyui`,
  `diffusers`, `onnx`, `python_video`; each one refuses honestly when it has
  nothing to run.
* `app/ai/health.py` - light and deep checks, plus the model-level check.
* `app/ai/models.py` - discovery that finds files without loading them.

### 1.2 Video Studio and the library

* `app/ai/video.py`, `app/ai/video_validation.py` - the five modes, capability
  checks, and reading a finished clip back before calling it a result.
* `app/ai/video_library.py` - the index, the probe cache (`mtime_ns:size`
  fingerprint), the thumbnail cache, search/sort/filter/paging.
* `app/ai/video_library_jobs.py` - the five library jobs (scan, import,
  thumbnails, remove, recheck) with the same shape as every other job.
* `app/ai/integration.py` - `clip_metadata`, `send_to_project`, `send_to_scene`,
  `send_to_timeline`, `make_video_scene`.
* `app/ui/views/video_library_view.py`, `app/ui/preview.py` - the page, and
  playback that is feature-detected instead of assumed.

### 1.3 Orchestration

* `app/ai/jobs.py` - the eight job states, the registry the queue reads, duplicate
  refusal, cancellation, and `retry_of` so a retry chain is visible.
* `app/ai/history.py` - one history for images and video, with the request kept.
* `app/ui/views/ai_studio_view.py` - the queue UI, backend/model pickers, the
  real Retry, and the storyboard approval flow.

### 1.4 The command line

`mgs ai backends|models|check|selftest|job status|video|image|storyboard` and the
new `mgs ai library list|inspect|thumbnail|scan|add|recheck|remove|thumbnails`,
all sharing the GUI's services.

## 3. Bugs this stage found and fixed

Each one has a regression test; none of them was left as "known behaviour".

1. **`log_event(level="WARNING")` raised.** Every Stage G warning path passed the
   level as a *string*, and `log_event` demanded an int - so the code that
   reported a problem was itself the problem (`TypeError: level must be an
   integer`). `log_event` now accepts a name or an int, with
   `tests/test_video_library.py::test_log_event_accepts_a_level_name`.
2. **A tool object was passed to the operating system as a program.** Thumbnail
   creation handed `FFmpegTools`/`FFmpegDiscovery`'s `ToolInfo` straight to
   `subprocess`, which failed with *"the program could not be started"*. The
   path is now unwrapped in one tested helper
   (`test_the_ffmpeg_binary_is_a_path_in_every_shape`).
3. **A clip with no FFprobe was labelled broken.** `validate_video_file` returns
   `VIDEO_CHECK_NOT_AVAILABLE` when the *checker* is missing; the library treated
   that as `UNREADABLE`, which would have told every user on a machine without
   FFmpeg that their clips were corrupt. It now distinguishes "not measured here"
   from "not readable" (`test_without_ffprobe_a_clip_is_not_called_broken`).
4. **`refresh_exists()` wiped a real verdict.** Rescanning promoted every
   `UNREADABLE` entry back to `READY` because the file existed. Status now only
   moves on the "is the file there?" axis.
5. **`add()` blanked the status on the way out.** The last line of `add()` set
   `status = READY` unconditionally, undoing the measurement above it.
6. **A failed import said nothing.** `_on_job_finished` wrote the message and
   *then* refreshed the list, and refreshing an empty library overwrote it - so
   the user saw "The library is empty" after an import failed. The refresh now
   happens first, and a crashed job's error (what happened / why / what to do) is
   shown.
7. **A test-backend clip could claim a model.** `VideoEntry.is_ai_model` defaulted
   to `True` and `from_dict` filled a missing value with `True`, so an imported
   clip - or one made by the fixture - could appear as an AI result. It is now
   `False` unless something recorded that a real model ran.
8. **Retry never retried.** `retry_job` refused in every case with "press
   Generate again", so the button could not do anything. It now rebuilds and
   re-submits the *recorded* request for a failed or cancelled job, and refuses
   with the reason when the backend or model is gone.
9. **`FUTURE_PAGES` was stale.** The Video library was the last placeholder, so
   `tests/test_gui.py` started failing on a rule that no longer had anything to
   check. The rule now asserts the sidebar and the roadmap agree, and that every
   ready page is really built.

## 4. Deliberate refusals (the honesty list)

These are behaviours, not gaps:

| Situation | What happens |
|---|---|
| No model installed | "AI model not installed…" - no file, no placeholder |
| A fixture backend is chosen | It is labelled `TEST BACKEND` in the picker, the queue, the history, the library and the CLI |
| An operation the backend does not support | Refused before running, with a suggestion |
| A retry whose backend/model is gone | Refused by name; nothing is substituted |
| An output smaller than a video | `VIDEO_OUTPUT_TOO_SMALL`, job `FAILED` |
| A clip whose file has gone | Marked missing, kept in the list |
| A clip that cannot be measured here | `READY`, "not measured here" - never "broken" |
| Playback unavailable | The reason, plus the two things that work |
| The cloud adapter | `NOT SUPPORTED` - this build is local-first |

## 6. Manual verification pending (for a person)

These are the checks the directive calls manual, and they are still to be done by
a human on a Windows machine with the application open:

1. **Backends page** - every row shows a state, a reason and what to do.
2. **Deep check** - press it on a real backend and confirm the result file is
   really produced, then removed.
3. **Generate with no model** - the refusal, in words.
4. **Queue while it runs** - progress, elapsed, ETA, cancel, and that cancel
   really stops the child process (Task Manager, no zombie).
5. **Batch cancel** - the finished clips are still there afterwards.
6. **Video library** - scan, make pictures, search, sort, tag, favourite.
7. **Send to project / scene / timeline** - then open the project and check.
8. **Playback** - on Windows, play a clip in the application.
9. **Log** - every step above appears as an `EVENT=` line.
10. **Retry** - kill a backend mid-generation, then press Retry.

`scripts/stage_g_manual_matrix.py` prints this list with the app-specific
numbers filled in for the machine it runs on.
